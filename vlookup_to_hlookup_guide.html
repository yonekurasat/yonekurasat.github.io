Excel lookup functions VLOOKUP → HLOOKUP 図解・例題付き

VLOOKUPからHLOOKUPへの
移行ガイド

縦方向の検索を、横方向の検索へ置き換えるための実務ガイドです。構文の対応関係、データ配置の考え方、数式変換、エラー対策を1ページで確認できます。

推奨用途：社内教育・引き継ぎ・Excelテンプレート改修 印刷対応：ブラウザの印刷機能でPDF化可
1. 違いを理解する 2. 構文を置き換える 3. 移行手順 4. つまずき対策

まず結論：検索方向が変わるだけではなく、参照番号も変わります

VLOOKUPは「左端列」で検索して「指定した列」から返します。HLOOKUPは「上端行」で検索して「指定した行」から返します。移行時の最大ポイントは、列番号を行番号へ読み替えることです。

VVLOOKUP

検索キーが表の左端列にあるときに使います。下方向に並んだ項目を探し、右側の列から値を返します。

HHLOOKUP

検索キーが表の上端行にあるときに使います。横方向に並んだ項目を探し、下側の行から値を返します。

!移行の注意

単に関数名を置き換えるだけでは不十分です。表の向き、範囲、返す位置の番号を必ず見直します。

1. VLOOKUPとHLOOKUPの違い

名前のVはVertical、HはHorizontalです。実務では「検索キーがどこに置かれているか」で使い分けます。

VLOOKUP：縦に並ぶキーを探す

=VLOOKUP(検索値, 範囲, 列番号, FALSE)

HLOOKUP：横に並ぶキーを探す

=HLOOKUP(検索値, 範囲, 行番号, FALSE)

2. 構文の対応関係

VLOOKUPの第3引数は「列番号」、HLOOKUPの第3引数は「行番号」です。ここを間違えると、正しい範囲を指定しても別の値を返します。

観点VLOOKUPHLOOKUP移行時の考え方
基本構文 =VLOOKUP(検索値, 範囲, 列番号, [検索の型]) =HLOOKUP(検索値, 範囲, 行番号, [検索の型]) 関数名だけでなく、第3引数の意味を必ず変更します。
検索する場所 範囲の左端列 範囲の上端行 検索キーを上端行に置いた表へ変換します。
返す位置 範囲内の何列目か 範囲内の何行目か 「在庫が3列目」だったなら、横持ち表では「在庫が3行目」になるか確認します。
完全一致 FALSE または 0 FALSE または 0 通常のID検索・コード検索では完全一致を明示するのが安全です。
近似一致 TRUE または省略 TRUE または省略 並べ替え条件が必要です。移行時は省略せず意図を明示します。
例変換イメージ
移行前: =VLOOKUP(G2, $A$2:$D$6, 3, FALSE)
移行後: =HLOOKUP(G2, $B$1:$F$4, 3, FALSE)

この例では、VLOOKUPで3列目にあった「在庫」が、HLOOKUP用の横持ち表では3行目に配置されているため、第3引数は3のままです。常に同じ数字になるわけではないため、表の配置を確認してください。

実例：商品IDから在庫数を取得する

移行前：縦持ちの表

商品ID価格在庫担当
A-0011,20025佐藤
A-0029808田中
A-0031,45018鈴木
=VLOOKUP(G2, $A$2:$D$5, 3, FALSE)

意味：G2の商品IDをA列で探し、同じ行の3列目、つまり在庫を返します。

移行後：横持ちの表

商品IDA-001A-002A-003
価格1,2009801,450
在庫25818
担当佐藤田中鈴木
=HLOOKUP(G2, $B$1:$D$4, 3, FALSE)

意味：G2の商品IDを1行目で探し、同じ列の3行目、つまり在庫を返します。

!範囲指定の落とし穴

HLOOKUPの範囲は、検索キーがある上端行を含める必要があります。上の例なら $B$1:$D$4 の1行目に商品IDがある状態です。検索キーが範囲の2行目以降にあると正しく検索できません。

3. 移行手順

既存ブックのVLOOKUPをHLOOKUPへ変換する際は、次の順番で確認すると安全です。

検索キーの位置を確認
→
表を横持ちに再配置
→
行番号へ変換

VLOOKUPの役割を分解する

まず既存数式を「何を探すか」「どの表で探すか」「何列目を返すか」「完全一致か」に分解します。

=VLOOKUP(検索値, 範囲, 列番号, 検索の型)

検索キーを上端行へ配置する

HLOOKUPでは検索キーが範囲の上端行にある必要があります。元の縦持ち表を横持ち表へ変換する場合は、コピーして「行/列の入れ替え」で貼り付ける方法が便利です。

形式を選択して貼り付け行/列の入れ替えTRANSPOSE関数

返したい項目が何行目か数える

HLOOKUPの第3引数は、指定範囲の上から何行目を返すかです。表全体の行番号ではなく、指定した範囲内での相対的な行番号として数えます。

範囲内の行項目HLOOKUPの行番号
1行目商品ID検索対象なので通常は返さない
2行目価格2
3行目在庫3
4行目担当4

検索の型を明示する

ID、コード、社員番号、商品番号のように完全一致が必要な検索では、最後の引数に FALSE を入れます。省略すると近似一致として扱われるため、想定外の値が返る原因になります。

=HLOOKUP(G2, $B$1:$D$4, 3, FALSE)

絶対参照を設定してコピーに備える

同じ検索表を複数セルで使う場合、範囲を $B$1:$D$4 のように絶対参照にします。コピー時に検索範囲がずれてしまう事故を防げます。

HLOOKUPへ移行すべきかの判断基準

✓HLOOKUPが向いているケース
  • 検索キーが横方向、つまり1行目に並んでいる。
  • 月別、年度別、製品別など、列方向に比較軸を並べたい。
  • 横長の帳票やダッシュボードに合わせて値を取りたい。
  • 元データを横持ちにする運用がすでに定着している。
×移行しない方がよいケース
  • 検索キーが左端列に自然に並んでいる。
  • データ件数が増えるたびに列が増え、横に伸びすぎる。
  • テーブル機能やピボット集計など、縦持ち前提の処理が多い。
  • 将来的にXLOOKUPへ統一する方針がある。
補現代Excelでの選択肢

新しいExcel環境では、XLOOKUPを使うと縦方向・横方向のどちらにも対応しやすく、完全一致が既定です。既存資産や互換性の都合でHLOOKUPへ移行する場合でも、長期的にはXLOOKUPへの統一も検討対象になります。

4. よくあるエラーと対策

症状主な原因対策
#N/A が出る 検索値が上端行に存在しない。文字列と数値が混在している。余分な空白がある。 検索値と上端行のデータ形式を揃えます。必要に応じて TRIM や VALUE を使います。
別の商品・別の月の値が返る 第4引数を省略し、近似一致になっている。 FALSE を明示します。コード検索では原則として完全一致にします。
返す項目がずれる 第3引数を列番号のまま考えている。指定範囲の開始行を含めて数えていない。 HLOOKUPでは「指定範囲内の上から何行目か」を数え直します。
コピー後に結果が変わる 検索範囲が相対参照のまま動いている。 $B$1:$D$4 のように絶対参照にします。
#REF! が出る 指定した行番号が範囲内の行数を超えている。 範囲を広げるか、行番号を正しい値に修正します。

移行前レビュー用チェックリスト

数式レビュー

  • 検索値は正しいセルを参照している。
  • 検索範囲の上端行に検索キーがある。
  • 第3引数は列番号ではなく行番号になっている。
  • 完全一致が必要な箇所は FALSE を指定している。
  • コピーする数式では検索範囲を絶対参照にしている。

データレビュー

  • 上端行の検索キーに重複がない。
  • 文字列・数値・日付の形式が揃っている。
  • 余分な空白や非表示文字がない。
  • 横持ち化しても今後のデータ追加が無理なく運用できる。
  • HLOOKUPよりXLOOKUPやINDEX/MATCHが適していないか確認した。

そのまま使える数式テンプレート

必要に応じてセル番地だけ置き換えて利用してください。

基本形：完全一致

=HLOOKUP(検索値セル, 検索表範囲, 返したい行番号, FALSE)

見つからない場合に空欄を返す

=IFERROR(HLOOKUP(検索値セル, 検索表範囲, 返したい行番号, FALSE), "")

検索値の前後空白を除去して検索する

=HLOOKUP(TRIM(検索値セル), 検索表範囲, 返したい行番号, FALSE)

月別の横持ち表から値を取る例

=HLOOKUP("2026年4月", $B$1:$M$8, 5, FALSE)
